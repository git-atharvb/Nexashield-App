TEST CASE 3: ACTIVE SOCKETS VS. ATTACK SURFACE (OPEN LISTENING PORTS)
================================================================================
Objective:
Demonstrate the vulnerability attack surface scanner and live socket tracking.

Steps:
1. By default, "🔗 Active Sockets" is active:
   - Shows all active outbound/inbound connections established by processes.
   - Note the status badges (● ESTABLISHED, ● TIME_WAIT, ● CLOSE_WAIT).
2. Click "🛡 Attack Surface (Open Ports)":
   - The button highlights orange.
   - The table immediately filters to all local ports currently in LISTEN state
     (TCP listening daemons & UDP listening sockets).
   - Points out exposed services (e.g. RPC 135, SMB 445, RDP 3389, Web 80/443).
3. Switch back to "🔗 Active Sockets".

TEST CASE 3B: MULTI-PROTOCOL FILTERING & PACKET MONITORING
================================================================================
Objective:
Verify comprehensive monitoring and tracking across all protocols and packet types.

Steps:
1. In the toolbar, click the "🔌 Proto:" dropdown:
   - Notice the complete protocol spectrum:
     * All Protocols
     * TCP
     * UDP
     * HTTPS (TCP & QUIC/HTTP3 UDP)
     * HTTP
     * DNS (Domain Name Resolution)
     * SSH (Secure Shell)
     * RDP (Remote Desktop Protocol)
     * SMB (Server Message Block / NetBIOS)
     * DB (Relational & NoSQL Databases: MySQL, Postgres, MSSQL, Redis, Mongo)
     * ICMP (Raw packet telemetry)
2. Select "TCP":
   - The table filters to show all TCP sockets.
3. Select "UDP":
   - The table updates to show all UDP active transmissions or listening sockets.
4. Select "HTTPS":
   - Shows encrypted web and API traffic.
5. Select "All Protocols":
   - Restores the entire real-time socket table.
6. Check the "🌐 NIC:" dropdown:
   - By default shows "All Interfaces" with aggregate network throughput and total
     packet counters (Sent/Recv, Drops, and Errors).
   - Switch to "Wi-Fi" or "Ethernet" to view adapter-specific hardware telemetry.
