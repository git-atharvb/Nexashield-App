TEST CASE 6: DEEP-DIVE PROCESS FORENSICS DOSSIER
================================================================================
Objective:
Demonstrate in-depth endpoint security investigation capabilities for any process.

Steps:
1. Click on any process in the table (e.g., "explorer.exe", "svchost.exe", or
   "python.exe").
2. The 440px "🔬 Process Forensics Dossier" drawer opens immediately on the right.
3. Expected Result:
   - Instant 0ms header preview while background ForensicWorker extracts deep data.
   - Full dossier loads with:
     a) AI VERDICT BANNER:
        - Risk score percentage, severity level, and dynamic reasoning text
          explaining why the AI assigned this score.
     b) BINARY IDENTITY & INTEGRITY:
        - Executable path
        - SHA-256 cryptographic hash (verified live from binary)
        - Binary size on disk
        - Full command-line arguments and Working Directory
        - Parent process lineage (Parent name & PPID)
        - User privilege level (👑 Elevated / System vs 👤 Standard User)
     c) RUNTIME & TELEMETRY FORENSICS:
        - Process start time and uptime clock
        - Active thread count
        - CPU user vs. kernel times
        - RAM working set (RSS), peak memory, virtual memory, and page faults
        - Disk Read/Write MB & actual I/O operations count
        - Voluntary & involuntary CPU context switches
     d) NETWORK SOCKETS:
        - Table of active outbound network connections (Protocol, Local, Remote, State)
     e) FORENSIC RISK INDICATORS:
        - Path verification (Trusted system directory vs Temp / AppData warning)
        - Network exposure & lineage integrity checks

TEST CASE 9: PROCESS CONTROLS (SUSPEND / RESUME / KILL)
================================================================================
Objective:
Demonstrate active endpoint mitigation controls and SIEM event logging.

Steps:
1. Select the checkbox next to a test process (e.g. `notepad.exe` or `calc.exe`).
2. Click "⏸ Suspend" in the toolbar -> Status changes to "● SUSPENDED".
3. Click "▶ Resume" -> Process resumes execution.
4. Select the checkbox and click "⛔ Kill Process":
   - Confirmation dialog appears with the count of processes.
   - Confirm termination.
   - Process is killed and disappears on the next refresh.
5. Navigate to the "SIEM / Logs" tab:
   - Confirm a "Warning" log entry is recorded:
     "Terminated process '<name>' (PID: <pid>)".
